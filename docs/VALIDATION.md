## Reproduce the automated checks

```sh
python3 lean/build.py
python3 lean/test_service.py
python3 -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.mjs
swift test --package-path native
```

The Python bridge suite uses local loopback sockets and short-lived test
processes. It tests malformed input, origin/host restrictions, process timeouts,
restart behavior, response/request association, and the absence of an algebra
fallback when Lean is unavailable. Its real-engine integration test requires
the executable to have been built first.

The JavaScript tests check exact fraction presentation, input snapshots,
malformed/stale response rejection, serialized/coalesced requests, failure
recovery, current controller rays, and restoration of camera/projection state.
They do not instantiate a browser WebXR session.

For the native decoder and live-model sequence, first run `./scripts/run.sh` in
another terminal, then follow the compiler and test commands in
[native/README.md](../native/README.md). The recorded native environment used
Xcode 27.2 beta with Swift 6 and the visionOS 27.2 Simulator SDK.

## Exact scope of the mathematical evidence

The kernel checks general statements about the explicit Grassmann generated
provider and integer service wrappers. These include agreement with coordinate
formulas, self-wedge zero, swapped-volume sign, and zero volume for the exact
dependent construction `c = a + b`. They do not characterize every dependent
triple or prove client rendering code.

The executable tests separately compare actual generated-kernel outputs with an
independent integer wedge/determinant oracle. Neither those finite tests nor a
successful axiom audit certify the compiler/runtime, implementation caches,
HTTP/JSON transport, pointer projection, RealityKit, Three.js, or physical
headsets. Each live displayed answer is a calculation, not a newly emitted proof
term checked by the kernel.

The UI uses quarter-unit input coordinates. Its exact integer outputs are scaled
by 16 for bivector coefficients and 64 for signed volume. Mesh coordinates and
camera operations use floating point. A bridge failure preserves the previous
accepted geometry and marks it as stale; native exported presets are labeled as
playback rather than live computation.

## Remaining limits

- Live algebra runs on the Mac; the native app does not contain a Lean runtime.
- The server defaults to loopback HTTP. Native use from another device needs an
  explicitly reachable Mac address. WebXR in a headset browser additionally
  needs a secure context; plain LAN HTTP is insufficient.
- Input components are bounded to `[-12,12]` integer quarter units. Arbitrary
  real coordinates and arbitrary-dimensional geometric algebra are outside
  this demo's interface.
- Simulator builds, model tests, and screenshots do not imply physical-device
  compatibility, frame rate, gesture quality, accessibility, or comfort.
