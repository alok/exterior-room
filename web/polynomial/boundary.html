Moving through the picture does not prove the picture correct. This page describes the actual boundary.

Kernel-checked

Nine base integer laws prove the display norm and Lorentz/discriminant identities, quadratic scaling and sign invariance, equivalent coefficient/display plane incidence, incidence of both inputs in the unnormalized dual-cross plane, and invariance of zero incidence under nonzero scaling of its normal. They concern the actual functions in lean/Polynomial/Core.lean. Axiom audits report only standard Lean axioms; there are no admitted proofs.

Eight additional Möbius-action laws check identity, determinant multiplication, left composition, discriminant scaling, plane-incidence covariance, scalar compatibility, adjugate inversion and agreement of returned rows with the action. These concern Polynomial/Transform.lean and TransformProofs.lean.

Computed by executable Lean

Canonical ball asks the Mac’s compiled Lean service to enumerate signed nonzero integer polynomials in a fixed ball, preserving multiples. Source depth separately enumerates upper forms by transformed trace and other forms by transformed radius, using exact integer predicates. Source caps are explicit; local domain/resource limits reject a replacement and retain accepted state. It returns exact coefficients, coordinates, discriminants, categories and gcds. Selection returns a polynomial label, rational projection and symbolic root. Plane requests return exact normals, rational/surd endpoints and membership indices. Every canonical crop through radius 96 was compared with a pinned independent implementation: 1,852,484 points at the largest crop.

Enumeration completeness, gcd normalization, radical simplification, JSON and the compiler/runtime are tested; they are not established by these algebraic theorems. A live response is a calculation, not a fresh kernel proof certificate.

Source depth uses a separately pinned original Starscape catalogue. The five initial source fixtures agree exactly, while two tested floating-point boundary cases differ from its deployed numerical code. Source recropping currently occurs on accepted release, not continuously during dragging. No catalogue enumeration-completeness theorem or source projection morph is claimed.

Möbius preview and commit

Continuous dragging uses a floating-point transvection. On release, a bounded integer matrix M is submitted to Lean. Its positive determinant D defines g = M/√D; the coefficient action is exactly J(M)/D because the square root cancels. Lean returns integer numerators and D, and the renderer converts that accepted rational action to floating point. This commits a declared rounded sample, not the exact real-valued pointer path. Snap’s numerical choice of an integral matrix is also outside the proof boundary; applying the chosen matrix is executable Lean.

Renderer and input

JavaScript formats immediate hover labels from Lean-exported coefficients, converts exact values to floating point, builds radial images and plane meshes, interpolates colors, sizes points, picks rays and moves cameras. RealityKit handles the corresponding native scene. Neither renderer is kernel-verified. The browser has no JavaScript cloud enumeration or discriminant/plane fallback.

Evidence categories

Desktop browser interaction, emulated WebXR, native simulator and physical headset tests are different evidence. The explicitly flagged QA harness exercises the real Three.js XR handlers with synthetic devices and a normal WebGL framebuffer. It cannot establish headset tracking, comfort, permissions or compositor behavior. Consult the repository’s dated acceptance receipt for which checks actually ran.

Provenance

The signed coefficient-space construction follows Katherine Stange’s talk and Starscape/Lattice work. Renderer conventions and modules are adapted from FareyVision commit ca809d2975a37a318a425e4b9dd73560b07faf39, with GPL notices preserved. The Möbius action follows Harriss–Stange–Trettel, with a separately pinned canonical formula module and interaction contract recorded in the repository. The new Lean implementation and proofs are this project’s work; they are not attributed to Stange. The separate exterior-algebra room uses the pinned Grassmann codebase.
